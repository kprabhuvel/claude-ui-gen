---
name: Comment sparingly
description: Only add comments for genuinely complex code; avoid obvious or redundant comments
type: feedback
---

Use comments sparingly. Only comment code that is complex or non-obvious.

**Why:** User preference — comments on straightforward code add noise without value.

**How to apply:** Do not add comments to self-explanatory code, simple functions, or standard patterns. Reserve comments for tricky logic, non-obvious algorithms, or subtle decisions that cannot be expressed clearly through naming alone.
